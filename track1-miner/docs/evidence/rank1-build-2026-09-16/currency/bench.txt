CURRENCY_EXCHANGE — champion-scorer sensitivity bench, 2026-09-16
==================================================================

WHAT THIS IS, AND WHAT IT IS NOT.

This is NOT a correctness bench against a known-good crossing reference. There is
no such reference for CURRENCY_EXCHANGE: nobody crosses (5 of 54 epochs per the
header of src/currency.ts), the whole field sits near zero, and we cannot see
scorer ground truths (GAPS G24). This run measures ONE thing only: how the
CURRENCY_EXCHANGE champion (registration 2945) responds to controlled edits of
OUR OWN current answer text, against ONE authored reference, for ONE live
question. It is a relative-sensitivity probe, not a validation that our answer
is correct, and it must not be read as one.

Per instructions, the live answer SHAPE in src/currency.ts was NOT changed based
on this table. That is the integrator's decision, not this bench's.

READING IT

1. Confirms the existing header comment in src/currency.ts almost exactly:
   an exact-matching figure scores ~1.0 (0.99995 here); missing it by ANY
   amount tested — 0.1% up to 5% — collapses the score to a tight band
   around 2.0e-7 to 2.07e-7. There is no visible gradient inside that band:
   0.1% off and 5% off score within about 3% of each other, both around
   2e-7, both effectively "wrong." This matches the file's documented
   "off by one part in a thousand: 2.06e-7 / off by half a percent: 2.03e-7"
   entries almost to the digit. Wording is not the lever; the number is.

2. A wording interaction that looks counter-intuitive and is reported, not
   explained: with the rate held an EXACT match throughout,
     - full text (rate + inverse clause + date/source sentence)   -> 0.999948 (high)
     - rate + date/source sentence, NO inverse clause              -> 0.999948 (high)
     - rate + inverse clause, NO date/source sentence               -> 2.48e-7 (near zero)
     - bare rate only, no inverse clause, no date/source sentence   -> 0.999949 (high)
   Dropping the date/source sentence while KEEPING the inverse clause is the
   only variant tested that tanks the score despite an exact-matching
   primary figure. Dropping both the inverse clause and the date/source
   sentence together (the bare case) does not. This was not investigated
   further — it would mean reading the scorer's own extraction logic, which
   is out of scope here — and it is exactly the kind of finding the task
   said to report rather than act on. No line of src/currency.ts's answer
   SHAPE was changed on the strength of this table.

CAVEATS (unverified, in order of importance)

- No validated crossing reference exists for this intent at all (see header
  above); this bench cannot and does not claim our answer is factually
  correct, only how the scorer reacts to edits of it.
- One question, one reference, one run. Not repeated, not run against a
  second live question, no confidence interval.
- The registry's declared wasm_hash for reg2945 does not match this file's
  plain SHA-256 (see METHOD). The file loads and scores in the exact pattern
  the existing source-code comments predict, which is strong circumstantial
  evidence it is the right binary, but the hash itself was not reconciled.
- champions/currency_exchange_reg2945.wasm is gitignored (binaries are never
  committed) and was freshly downloaded for this run; it is not present in
  this worktree's git history.
