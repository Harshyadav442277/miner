`docs/openapi.json` is generated by `tools/openapi.py` (PyYAML) from `miner.yaml` and from one real production
answer per route (`samples.json`, taken by `tools/openapi-check.mjs`).

| | |
|---|---|
| Operations | 35, one per endpoint, covering all 36 intents |
| Query parameters | 94, with the manifest's descriptions and required flags |
| Shared answer fields | 80: the registered `output_schema`, plus `answer`, `error`, `checked_at` and `receipt` |
| Route-specific fields | typed from a production answer and marked `x-observed` |

## Checked

- **First check:** against live production (`miner-mz9gh2afy`), one question per route. Production returned
  **101 top-level fields that the registered `output_schema` does not name** (G211), including every
  company-registry field and every conversion figure.
- **After adding the observed fields:** a second run with fresh answers found **0 undocumented fields**
  (`check-production.txt`).
- **Structural check:** 35 operations, every `$ref` resolves, every operation has a 200 response, and every
  parameter has a name, location and schema.
- **Not validated** with a formal OpenAPI validator: none is installed, and none was downloaded.

## Limits

- **One sample per route.** A field that was null in the sample is marked "type not observed" rather than
  typed as null. A field that appears only in other cases (some errors, multi-label answers) may be missing.
- **The registered `output_schema` in `miner.yaml` is still incomplete.** That file is hashed into registration
  4829 and changes only with the next `updateMiner`; this spec is where to regenerate it from.
